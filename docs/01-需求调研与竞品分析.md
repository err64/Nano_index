# 01 需求调研与竞品分析

> Veriforge 官方网站 · 立项调研文档 · 2026-10-06

## 1. 项目背景

**Veriforge**（NANOFACTORY 出品）是一个生产级、可验证的 AI 编码工人执行框架（Worker Harness）与控制平面。它接收强类型的 `CodingTaskContract`，在隔离的 Git Worktree 中驱动 Codex CLI、Claude Code 等 Coding Runtime 执行代码修改，通过阶梯式防篡改验证（BASELINE / FAST / FULL / PROTECTED / SYNTHESIZE）与完成门禁（Completion Policy）检验交付物，并产出带机器验证证据链的结构化结果（`WorkerResult`）。

产品本体已完成：确定性 FSM 状态机、受保护验证与测试弱化检测、失败指纹、预算内修复循环、SQLite 租赁队列调度、Transaction Outbox 交付（GitHub PR 幂等创建）、零框架 Web 控制台，以及 70+ 文件、450+ 用例的自动化测试防护网。

**官网目标**：为该产品建立对外的品牌门户与获客入口，向工程团队清晰传递"AI 写码，证据说话"的核心价值，并支撑试点合作转化。

## 2. 目标用户与核心诉求

| 用户角色 | 关注点 | 官网需要回答的问题 |
| :--- | :--- | :--- |
| 平台 / 基础设施工程师 | 能否私有部署、如何接入现有 Git 流程、资源占用 | 部署形态、系统要求、集成方式、快速上手路径 |
| 工程效能 / 研发负责人 | AI 编码产出能否被信任、误报率、返工成本 | 验证机制原理、防作弊设计、证据链样例 |
| CTO / 安全负责人 | 代码与凭据是否出内网、审计合规 | 私有化架构、凭据隔离、RBAC、审计与备份 |
| 开发者社区 | 是否开源、上手成本、技术深度 | MIT 许可、Demo 路径、文档与 FAQ |

**关键结论**：受众是技术决策者，官网必须"用工程语言讲工程事实"，拒绝营销空话；核心转化路径为「理解机制 → 看到证据 → 本地跑通 → 联系试点」。

## 3. 竞品分析

### 3.1 竞争格局

| 竞品 | 定位 | 与 Veriforge 的关系 |
| :--- | :--- | :--- |
| Codex CLI / Claude Code | AI 编码执行器（Coding Runtime） | **集成对象而非竞品**。Veriforge 在其之上提供验证与编排 |
| GitHub Copilot coding agent | 云端托管编码 agent，产出 PR | 云端、闭环在 GitHub 内；无受保护验证、无防篡改证据链、不可私有化验证逻辑 |
| Devin（Cognition） | 全自主云端开发者 | 端到端黑盒程度高，用户难以审计"为什么算完成" |
| OpenHands 等开源 agent 框架 | 通用 agent 运行环境 | 验证以沙箱内测试通过为准，模型可跳过/弱化测试；无完成判定权分离 |
| SWE-agent / Aider 等 | 研究 / CLI 工具 | 面向基准与个人使用，无生产调度、交付编排与审计面 |

### 3.2 差异化维度（官网叙事骨架）

1. **完成判定权归属**：Coding Runtime 永不拥有最终完成判定权，由 Harness 纯代码裁决。
2. **防篡改验证**：受保护验证强制恢复 Base Commit 原始测试执行；静态与 Diff 级检测 `.skip`、断言删除等弱化行为。
3. **机器证据链**：每个验收标准绑定真实进程退出码、耗时与失败指纹，`WorkerResult` 机读、抗篡改。
4. **预算内自治**：迭代数、运行时长、成本三重硬预算，指纹重复即判无进展并熔断。
5. **私有部署**：默认回环绑定、RBAC Token、SSRF 防护、SQLite 热备份，数据不出内网。

**官网定位语**：不与模型厂商比"谁更会写码"，而是建立"谁说了算"的可信验收层。

## 4. 网站需求清单（业务 → 功能映射）

| 业务需求 | 功能承载 |
| :--- | :--- |
| 品牌形象与核心价值传递 | 首页 Hero、三大支柱、数据事实条 |
| 机制可信度证明 | 验证阶梯可视化、真实控制台截图、案例页证据摘录 |
| 快速上手 | 帮助中心（安装/构建/Demo/控制台四步）、CLI 命令速查 |
| 试点合作转化 | 全站 CTA「申请试点」、关于页表单（≤3 次点击触达） |
| 持续内容运营 | 新闻动态页 + JSON 内容模型 + 轻量 CMS 后台 |
| 招聘与生态 | 关于页角色卡片、真实集成生态墙 |

## 5. 约束与风险

- **性能硬指标**：首屏 < 2s、Lighthouse ≥ 90 → 采用零框架静态页 + 系统字体 + 内联 SVG + 延迟加载。
- **内容真实性**：团队成员、合作伙伴暂无公开资料 → 用角色卡片与真实集成生态（Codex/Claude Code/GitHub 等来自 README 的事实）替代虚构信息；上线前需替换的占位内容在 README 中逐项标注。
- **无后端表单服务**：联系表单先以 mailto 协议落地，CMS 服务端预留收件扩展点。
- **品牌一致性**：官网沿用 Veriforge 控制台的设计语言（深色工程控制台、熔钢渐变印章 Logo），避免两套视觉。

## 6. 结论

立项通过。设计基调为「深色锻造工程风」（Dark Forge Engineering），站点为多页静态架构 + 零依赖 Node 内容服务，详见 `02-功能架构.md` 与 `03-视觉设计规范.md`。
