首页 项目介绍

大模型不缺能力，缺一条它不能篡改的验收线。

当模型既当答题人又当裁判，测试可以被跳过、断言可以被删除、死循环会烧光预算。Veriforge 从第一天起把完成判定权从模型手里拿走。

为什么需要它

LLM 落地软件工程的常见隐患，不是「写不出代码」，而是「自称写完了」。

  • 自我评估不可信
    让模型既执行又验收，测试用例被擅自 .skip、断言被删除、失败被轻描淡写。
  • 无限循环烧预算
    同一个错误反复尝试，Token 与时间在死循环里耗尽，没人知道该在哪儿叫停。
  • 交付不可审计
    「我觉得改好了」没有留痕：改了什么、跑过什么测试、凭什么算通过，全部无据可查。

核心优势对照

与「让模型自己跑测试」的常见做法相比，差别在判定权与证据，不在模型强弱。

维度Veriforge常见做法
完成判定 Harness 纯代码门禁裁决，模型无判定权 模型自评「已完成」，人来兜底
测试真实性 受保护验证强制恢复原始测试，弱化检测双保险 测试可被模型修改或跳过
执行隔离 独立 Git Worktree + 环境变量白名单 直接在源仓库工作，凭据暴露面大
成本控制 迭代数、时长、成本三重硬预算，指纹熔断 提示词里「请别死循环」
交付审计 WorkerResult 机读证据链，命令退出码留痕 聊天记录截图当交付物
部署形态 单机私有化，SQLite 零中间件，代码不出内网 依赖云端服务或重型集群
